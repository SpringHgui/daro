# daro-rs 交互细节台账

对照基准：本机安装的对照程序。
本文件记的是「实测到什么数 / 差在哪 / 改了没有」，和 [FEATURES.md](FEATURES.md) 的
功能清单分工不同：FEATURES 记「入口能不能点通」，这里记「点下去像不像」。

## 测量方法（可复现）

- 显示器 3840×2160 @200%，截图与坐标都是**物理像素**，逻辑像素 = 物理 / 2。
- 探针脚本在 `.scratch` 下的取证脚本：
  - `capture(hwnd, path)`：PrintWindow，抓客户区；
  - `real_click/real_move/send_text`：SendInput 真输入（**PostMessage 的鼠标消息 Qt 会丢**）；
  - `foreground(hwnd)`：AttachThreadInput 绕过前台锁（否则点击落到别的窗口上）；
  - `popup_menu(hwnd)` + `dump_menu_hmenu`：右键菜单是原生 `#32768` 窗口，
    用 `MN_GETHMENU`（0x1E1）取 HMENU 后逐项读状态。菜单文字是 owner-draw，
    `GetMenuItemInfo` 拿不到文本，只能截图看字（结构/灰态能读）。
- 坑：参考界面主窗的截图包含原生标题栏（58 物理像素），
  而 `ClientToScreen` 的客户区原点在标题栏之下 —— 点树行时 `client_y = 截图 y - 58`，
  否则会稳定点错一行。

## 图标重绘（2026-10-31）

参考界面那批图标是**多色 + 立体感**的（蓝表 / 红窗 / 绿加号 / 铜色 Ent 角标），
原来的 daro-rs 用的是 lucide 单色线稿，这是「界面还原度」最扎眼的一处。

### 为什么没用位图 / SVG

- GPUI 的 `svg()` 走 `svg_renderer::render_alpha_mask`：SVG 先被光栅化成**单色 alpha 蒙版**，
  再用一个 `text_color` 上色。彩色 SVG 进去，出来只剩一种颜色 —— 那批图标恰恰是多色的。
- 位图在右侧信息卡的 60+ px 大图上会糊，且明暗主题 / 任意 DPI 都要额外维护多份。
- 例外：连接/引擎 logo 与库圆柱直接复用老版 daro 的彩色 SVG，走 `img()` +
  `Image::from_bytes(ImageFormat::Svg)`（resvg 全彩光栅化，见 `src/db_icons.rs`），
  不受 `svg()` 单色蒙版限制。

### 做法

新增 `src/art.rs`：用 `canvas` + 四边形 / 多边形 / 折线 / 三次贝塞尔自己画，
坐标统一落在 **24×24 设计格**里，绘制时按目标尺寸整体缩放。于是同一份图标
既能喂 15～16px 的树行与对象列表，也能喂 62px 的信息卡大图，任意 DPI 都清晰。

| 位置 | 图标 |
|---|---|
| 功能区 13 项 | 插头 + 绿加号 / 红蓝双窗 / 蓝表 / 表 + 眼镜 / 红表 + 眼镜 / f(x) / 黄衣人像 / 工具托盘 / 红蓝双窗 / 灰块 + 循环箭头 / 青绿机器人 / 橙色立方体 / 紫色柱图 |
| 功能区角标 | 备份 / 自动运行 / 模型 / BI 右下压橙色 `Ent` 角标（与参考一致） |
| 左树 | 分组黄文件夹、连接用老版厂商 logo（`assets/icons/engines/*.svg`，MySQL 海豚 / PG 大象 / SQL Server / SQLite …）、库节点用老版绿色圆柱（`assets/icons/ui/database.svg`）、模式三绿块拓扑图、表 / 视图 / 实体化视图 / 函数 / 查询、字段 |
| 对象面板 | 表行与卡片：深蓝表头 + 2×2 棋盘表身（取样 `#0a7cd4` / `#cee8ff` / `#94cff9` / `#adddff` / `#7cc3f9`） |
| 工具条 | 打开表 / 设计表 / 新建表 / 通过 AI 新建表 / 删除表 / 导入 / 导出 |
| 右侧信息卡 | 62px 大图标：表卡片、老版绿色库圆柱、绿色模式拓扑图（深绿表头 `#0b7a3f` + 体 `#3ec488` + 线 `#5d6f80`），与参考同一套取样色 |

单色线稿仍可通过 `art::Glyph::Lucide(IconName)` 使用；`From<IconName>` 会把
常用几款（Table2 / Eye / Layers / SquareFunction / SquareTerminal / Database /
Folder* / Boxes）自动映射到重绘版，所以老的调用点不必逐个改。

### 自动更新：装不上的根因与修复（2026-11-12）

用户回报「0.0.13 点立即更新，下载完成、重启后还是 0.0.13」。复现结果：`%TEMP%\daro-update`
里安装包在、安装器日志也在，系统里装的还是旧版。

**根因**：安装包要覆盖 `daro-mcpd.exe`。它是独立常驻进程，不归 Restart Manager 管
（日志 `RestartManager found an application using one of our files: daro-mcpd.exe` →
`Some applications could not be shut down`）；配合 `/SUPPRESSMSGBOXES`，Inno 的
「无法关闭应用程序」提示框默认选「中止」，安装器以退出码 5 直接退出，脚本接着按
InstallLocation 拉起的还是旧版 —— 看起来像「重启了却没更新」。只有开着 MCP 后台
（`mcp.json` enabled）的机器会中招。

| 事项 | 做法 |
|---|---|
| 安装前让后台退场 | 新增 `mcp::pause_for_update()`：先把开关落成关闭让 1s 轮询的后台自己退，3s 宽限后按心跳 `mcpd.json` 里仍活的 PID 结束（不碰自己的 PID），收尾把开关恢复原值；新版本启动时 `boot()` 照开关重新拉起 |
| 兜底强关 | 安装参数加 `/FORCECLOSEAPPLICATIONS`：其它还占着文件的进程由 Restart Manager 强关（日志 `Shutting down applications using our files. (forced)`） |
| 失败要能看见 | 加 `/LOG=<setup>.log`；退出码非 0 时写 `update-status.txt`（重定向必须放在 echo 前，否则 `echo 5>"f"` 被当成句柄 5 重定向）。更新中心下次打开，若同版本安装包还在且记录到失败，Ask 页直接说「上次安装未成功（退出码 N），点立即更新重试」 |

**验证**：`update::` 9 条（新增脚本参数 / 失败码解析两条），`tests/mcp.rs` 16 条（新增
`update_pause_stops_daemon_and_keeps_switch_on`：真起 `daro-mcpd` 再调暂停，10s 内退出且
开关仍为 true）；本机实测后台开着跑安装：日志出现 `(forced)`、退出码 0、无
`update-status.txt`，安装的版本号由 0.0.13 变为安装包版本。

**诚实边界**：0.0.13 自带的安装编排本身就是坏的，这次修复得先手动装一次才生效；
之后从修复版起自动更新才走上面这套流程。
