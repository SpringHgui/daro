# 一个把 Navicat 手感搬进 Flutter 的数据库客户端

> Navicat 好用，但它收费、只偏 Windows、换台机器一切重来。
> 我花了 15 天，用 Flutter 把那份「桌面级手感」复刻了一遍——**免费、开源、Win/Mac/Linux 通吃**。
> 顺手，还给它接上了一个能让 AI 直接替你干活的后门。

---

如果你管过数据库，大概率绕不开 **Navicat**。

那种感觉很难忘：左边一棵连接树，中间一屏表，右边一堆详情；双击就进表，密密麻麻的数据一屏塞得满满当当，数值右对齐、点哪儿都是「按下即响应」，没有半点拖泥带水。

**那就是「桌面工具」该有的样子。**

可现实是——它要钱，它最顺的是 Windows，你在 Mac 或 Linux 上凑合用，那份手感就打折。

所以我一直想做一件事：**把这套手感，原封不动搬到一个免费、开源、跨平台的东西里。**

用 Flutter，我试了。它叫 **daro**。

## 我说的「Navicat 手感」，具体是哪些东西

不是抄个界面就叫致敬。下面这些细节，是我一条条抠出来的：

- **三栏布局 + 顶部 Ribbon**：连接树 / 对象面板 / 详情区，跟 Navicat 一个肌肉记忆，老用户不用学。
- **桌面级密集网格**：行高压到 22、单元格可框选、数值列自动右对齐、编辑器进格不跳位——一屏能看到的信息量，是网页 UI 给不了你的。
- **按下即响应的零延迟执念**：选中、点击全走「按下瞬间触发」，砍掉了水波纹动画和那 300ms 的双击判定。「首次点击慢半拍」这种事，我忍不了，也见不得别人忍。
- **明暗双主题**：不是简单反色。每一档灰、每个 hover 色都按层级重调过，暗色下不发飘、亮色是干净的「纸白」。
- **中 / 英 / 日三语**：界面文案全部本地化，出海也能用。
- **文档式多标签**：每个「连接 + 库」一个独立标签页，自带历史与输出，切来切去不丢现场。

一句话：**你闭着眼睛知道下一步该点哪——这种感觉，才是桌面工具的灵魂。**

## 但它又不只是「复刻一个 Navicat」

如果只是复刻，那意义有限。真正让我得意的，是我给它接的这条新通路——**内置 MCP，让 AI 直接连库干活。**

传统客户端里，人永远是唯一的操作者：AI 帮你写了 SQL，你还得自己贴进去、点执行、看结果。

daro 想把「你」这个中间人**去掉**。

开启内置 MCP 服务后，兼容 MCP 协议的 AI（比如千问办公）就能像个「远程 DBA」一样调用它：查表结构、跑查询、必要时改库，全程走标准协议，不用你手动搬运。

而且权限是**分级、可控**的，每条连接单独设三档：

| 模式 | AI 能干什么 | 适合场景 |
|---|---|---|
| `read_only` | 只能查，不能改 | 数据审计、出报表 |
| `sandbox` | 能改表结构，不能跨库乱来 | schema 实验 |
| `agent` | 完全访问，含写操作 | 真·AI 运维 |

一条连接**没进授权名单，就是彻底拒绝**，所有调用吃闭门羹。

最关键的一点：**这个功能默认是关的。** 不装、不监听端口、不占资源；你不主动开，它就是个人畜无害的普通客户端。

> 安全感这东西，得还给用户。谁给你的勇气，让 AI 默认就能写生产库？没人。

## 能连哪些库，说清楚

别被「Flutter 写的桌面工具」劝退——它连的是**真数据库**，不是花架子。

当前**开箱可用 6 种引擎**：

- ✅ MySQL
- ✅ MariaDB
- ✅ PostgreSQL
- ✅ SQL Server
- ✅ SQLite（文件型，FFI）
- ✅ Access（ODBC，文件型）

规划中：Oracle / MongoDB / Redis / Snowflake。

而且**每个引擎能干啥，界面会自己显隐**：支持模式层的就显示模式层，能管角色的才给你管角色，不支持的直接不摆出来——不是「按钮全给你点上、点了报错自己扛」。
